Module 0 · Concept

The Four Words You'll Hear Constantly

Everything in Azure nests inside these containers. Get this hierarchy straight and the portal stops feeling like a maze.

Subscription

The billing boundary. Your Azure for Students account is one subscription with a $100 credit.

Resource Group

A folder for related resources. Delete the group, delete everything inside it — this is your cleanup button.

Region

The physical datacenter location running your resource, e.g. East US or Central India.

Resource

The actual thing — a VM, a storage account, a database. Everything else exists to organize these.

Rule of thumb for today: one resource group per student, named consistently. When the workshop ends, deleting that one resource group deletes everything you built.

Module 1 · Concept

Who Manages the Operating System?

Compute options sit on a spectrum of control vs. convenience. Today you'll build the same app both ways.

🖥️
Virtual Machine
  • You own the OS, patches, and runtime
  • Full control — install anything
  • You are the ops team
🚀
App Service
  • Azure manages the OS and platform
  • You just push code (git / CLI / CI)
  • Built-in scaling, HTTPS, deployment slots
Today's lab: deploy a Linux VM and SSH into it, then deploy the same simple web app to App Service in minutes. You'll feel the difference directly.
Module 2 · Concept

Structured Data vs. Everything Else

Almost every app needs both kinds of storage. Knowing which one to reach for is half the battle.

Need Use Why
Files, images, backups, logs Blob Storage Cheap, unstructured, scales to any size
Rows, relationships, transactions Azure SQL Database Schema, joins, ACID guarantees
Flexible JSON documents, global scale Cosmos DB Schema-less, multi-region, low latency
Today's lab: upload/download blobs from the CLI and SDK, then stand up an Azure SQL database with three tables (authors, publishers, books) and sample data. You'll finish by deploying a small Java REST API on your Module 1 VM that reads straight from those tables.
Module 2 · Concept

One VM, Three Running Services

Your Module 1 VM never went away \u2014 it's about to run a real, data-backed application alongside nginx and Flask.

Entity

A Java class annotated @Entity, mapped to an existing table \u2014 no schema generation, since the tables already exist.

Repository

One line of code (extends JpaRepository) gives you working database queries with zero SQL written by hand.

Controller

Maps HTTP requests like GET /api/authors to repository calls, returning JSON automatically.

Today's lab: scaffold this Spring Boot app directly on your VM, point it at the SQL database from 2D/2E, and confirm /api/authors, /api/publishers, and /api/books all return real rows.
Module 3 · Concept

Everything Is Denied by Default

A Virtual Network (VNet) is your private slice of the Azure network. Traffic only flows where you explicitly allow it.

VNet

Your isolated network space, carved into subnets.

NSG

Network Security Group — a firewall of allow/deny rules attached to a subnet or NIC.

Default Deny

Inbound traffic is blocked unless a rule explicitly opens the port.

Today's lab: put your Module 1 VM behind an NSG, then test what happens when you allow and deny specific ports.
Module 3 · Concept

Stop Putting Passwords in Code

Microsoft Entra ID (formerly Azure AD) handles who — and what — is allowed to do things in Azure.

The old way

Connection strings and keys hard-coded or dropped into config files. Anyone who reads the code gets full access.

Managed Identity

Azure gives your App Service its own identity in Entra ID. You grant that identity permission on your Storage Account — no secret ever touches your code.

Today's lab: assign a managed identity to your App Service and use it to read from Blob Storage with zero credentials in your app.
Module 4 · Concept

If You Can't See It, You Can't Fix It

Azure Monitor and Application Insights collect metrics, logs, and traces from everything you've deployed today.

Azure Monitor

Platform-level metrics — CPU, memory, request counts, response times — for every resource, with no code changes.

Application Insights

Code-level visibility — exceptions, dependency calls, custom events — wired into your App Service.

Capstone lab: wire Modules 1–3 into one flow — App Service → Managed Identity → Storage + SQL, behind NSG rules — then deliberately break something and diagnose it from the logs.
Before You Log Off

One Command, Full Cleanup

Everything you built today lives inside a single resource group. Deleting it deletes everything — and stops your credit from draining.

Cloud Shell 
az group delete \
  --name rg-netid-workshop \
  --yes --no-wait
Do this before you close your laptop. Full steps and a verification checklist are in the lab guide's final section.
