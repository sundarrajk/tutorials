Networking Foundations · Topic 1

OSI Model, TCP/IP Stack & Load Balancer Tiers

The OSI model is a conceptual framework with 7 layers. TCP/IP is the practical 4-layer implementation that runs the internet. Every packet you send travels down all layers on the sender and up all layers on the receiver — each layer adding or stripping its header.

Encapsulation — How Layers Work
  • HTTP message (Layer 7) → TCP adds port numbers (Layer 4) → IP adds source/dest IP (Layer 3) → Ethernet adds MAC addresses (Layer 2) → bits on wire (Layer 1)
  • Each layer only talks to the layer directly below/above it — a clean abstraction
  • The receiver reverses the process: strip each header going up
HTTP Lives at Layer 7
  • GET /index.html HTTP/1.1\r\nHost: google.com — this text is the Layer 7 payload
  • It is wrapped in a TCP segment, which is wrapped in an IP packet, which is wrapped in an Ethernet frame
  • A router at Layer 3 only looks at the IP header — never reads HTTP
  • A L7 load balancer reads HTTP headers to make routing decisions
Load Balancer Tiers
  • L7 LB (Application): reads URL, cookies, JWT tokens. Smartest, slowest. AWS ALB, nginx, Envoy. SSL termination here.
  • L4 LB (Transport): balances by TCP/UDP port. Fast, protocol-agnostic. AWS NLB.
  • L3 LB (Network): Anycast BGP. Same IP from many data centres — client routed to nearest. Cloudflare, AWS Global Accelerator.
Transport Protocols · Topic 2

TCP · UDP · Multicast

Three fundamentally different ways to send data. TCP guarantees delivery with a full handshake and acknowledgement cycle. UDP fires packets with no ceremony. Multicast efficiently delivers one stream to many receivers simultaneously.

TCP — The Three-Way Handshake
  • SYN: "I want to connect, my sequence starts at X"
  • SYN-ACK: "OK, my sequence starts at Y, I acknowledge your X"
  • ACK: "I acknowledge your Y — we're connected"
  • Data transfer is bidirectional — both sides can send simultaneously
  • Close: FIN→ACK→FIN→ACK (four steps, graceful drain of in-flight data)
  • Every segment has a sequence number; receiver reorders and ACKs
UDP — No Ceremony
  • No connection setup — first packet sent immediately
  • No ACK — sender doesn't know if packet arrived
  • No ordering — packets may arrive out of sequence
  • 8-byte header vs 20+ for TCP
  • Used for: DNS (1 request/response), video calls (stale frame is fine), gaming (latest position supersedes old), QUIC (HTTP/3 over UDP with reliability in user space)
Multicast — Efficient One-to-Many
  • Source sends ONE packet; network replicates at last hop
  • Receivers join a multicast group (224.x.x.x) using IGMP
  • Router knows which downstream ports have group members — copies only there
  • Saves enormous bandwidth vs sending N separate unicast streams
  • Used for: IPTV live TV, Bloomberg/Reuters market data feeds, corporate live events
Network Layer · Topic 3

IPv4 vs IPv6 — Why 4 Billion Wasn't Enough

IPv4 was designed in 1981 for a network of university computers. Nobody anticipated billions of smartphones, smart TVs, IoT sensors, and cloud servers. IPv6 solves the address exhaustion problem permanently — but IPv4 lives on via NAT.

IPv4 Exhaustion
  • 2³² = 4.29 billion addresses — sounded limitless in 1981
  • IANA last /8 block allocated February 2011
  • Asia Pacific (APNIC) ran out 2011; Europe (RIPE) 2019
  • IPv4 addresses now trade on secondary markets for $30–50 each
  • NAT bought a decade of extra time — but breaks end-to-end connectivity
IPv6 — Effectively Unlimited
  • 2¹²⁸ ≈ 340 undecillion (3.4 × 10³⁸) addresses
  • Every device on Earth could have trillions of addresses each
  • No NAT needed — every device gets a globally routable address
  • Simpler header (40 bytes, fixed length) vs IPv4's variable header
  • ~40% of global internet traffic is now IPv6 (Google statistics, 2024)
Why IPv4 Still Dominates
  • Installed base: billions of devices, routers, firewalls with IPv4
  • NAT works well enough for outbound connections (home users, mobile)
  • Dual-stack: most modern systems run both IPv4 and IPv6 simultaneously
  • Transition will take decades — many enterprise data centres still IPv4-only internally
  • Private address ranges (10.x, 172.16.x, 192.168.x) will remain in use forever
Application Layer · Topic 4

DNS — Recursive Resolution of google.com

The Domain Name System is a globally distributed, hierarchical database that maps human-readable names to IP addresses. Without DNS, you would need to memorise 142.250.189.206 instead of typing google.com. The diagram below shows every step of a fresh DNS lookup — animation cycles through the nine steps.

The Hierarchy
  • Root servers: 13 logical clusters (a–m.root-servers.net), hundreds of physical servers globally via Anycast. Know where each TLD lives.
  • TLD servers: Verisign runs .com/.net. ICANN delegates. Know which authoritative NS to use for each domain.
  • Authoritative NS: your registrar's server, or Route 53, Cloudflare DNS. Has your actual DNS zone records.
Caching — Why It's Fast
  • Every DNS response has a TTL. Once cached, steps 2–7 are skipped.
  • Your OS has a DNS cache. Your browser has one. Your ISP resolver has one.
  • Most lookups return in <1ms from cache. Cold lookup: 50–200ms.
  • Low TTL (60s): fast failover. High TTL (86400s): faster browsing, slower propagation of changes.
Key Record Types
  • A: hostname → IPv4 address
  • AAAA: hostname → IPv6 address
  • CNAME: alias → canonical name (www → example.com)
  • MX: mail exchanger — where to deliver email
  • TXT: arbitrary text — SPF, DKIM, domain verification
  • NS: which nameservers are authoritative for this zone
Application Layer · Topic 5

Registering a Domain, Website & Email

Owning a domain name is the foundation of every online presence. Three separate registrations — domain name, website hosting, and email hosting — each add their own DNS records, and DNS ties them all together.

① Register the Domain Name
  • Go to GoDaddy, Namecheap, Google Domains, or AWS Route 53
  • Search for mycompany.com → pay ~$10–15/year
  • Registrar notifies the TLD registry (.com = Verisign) that you own it
  • You can now control DNS records for mycompany.com
  • WHOIS privacy: hide your personal contact details from public database
② Register a Website
  • Get a server: AWS EC2, DigitalOcean, Netlify, Vercel, or shared hosting
  • Note the server's public IP address (e.g. 45.33.32.156)
  • Add an A record in your DNS panel: mycompany.com → 45.33.32.156
  • Add a CNAME: www → mycompany.com
  • Install TLS certificate (Let's Encrypt, free) → HTTPS works automatically
  • DNS propagation: ~5 minutes to 48 hours (TTL dependent)
③ Register Email (@mycompany.com)
  • Sign up for Google Workspace, Microsoft 365, or Zoho Mail
  • Provider gives you an MX record: mycompany.com MX mail.google.com
  • Add MX record in your DNS → email to @mycompany.com now routes to Google
  • Also add SPF, DKIM, DMARC TXT records (anti-spam proof)
  • Create user accounts (alice@mycompany.com, bob@mycompany.com) in admin panel
Application Layer · Topic 6

HTTP vs HTTPS — TLS Handshake

HTTP sends everything as readable text — anyone on the same network can read your passwords. HTTPS wraps HTTP inside TLS (Transport Layer Security), encrypting all data with AES-256 and authenticating the server with a certificate.

TLS Handshake (TLS 1.3)
  • ClientHello: "I support TLS 1.3, here are my cipher suites and a random nonce"
  • ServerHello + Certificate: chosen cipher, server's public key cert (signed by CA)
  • Certificate verification: browser checks CA signature, expiry, domain match
  • Key derivation: both sides independently compute the same session key (ECDHE)
  • All further traffic: encrypted with AES-256-GCM
  • TLS 1.3: 1-RTT (was 2-RTT in TLS 1.2) — faster startup
Certificates & Certificate Authorities
  • A certificate is a public key + domain name, digitally signed by a trusted CA
  • CA hierarchy: Root CA (in your OS/browser) → Intermediate CA → your cert
  • Let's Encrypt: free automated certificates, ~300 million active certs
  • EV certificates: Extended Validation — CA verified company identity (green bar)
  • Expired cert → browser shows red warning and blocks access
  • Certificate Transparency (CT) logs: all certs publicly logged, detectable forgery
Full URL-to-Page Flow
  • Type https://mycompany.com → DNS lookup (50–200ms cold, <1ms cached)
  • TCP connect to port 443 (SYN/SYN-ACK/ACK ~10–50ms)
  • TLS handshake (~10–30ms for TLS 1.3)
  • HTTP GET / → server returns HTML (<50ms for close servers)
  • Total: 150–300ms first visit · <50ms repeated visit (TLS session resume)
Application Layer · Topic 7

SMTP — How Email Travels Across Domains

Simple Mail Transfer Protocol (1982) is the standard for sending email between mail servers. A message from alice@company-a.com to bob@company-b.com hops through DNS, authentication checks, and spam filters before reaching Bob's inbox.

The SMTP Hops
  • Port 587 (submission): your mail client → your mail server (authenticated)
  • Port 25 (relay): mail server → remote mail server (MTA to MTA)
  • Port 465/993 (IMAP): your mail client downloads messages from server
  • DNS MX lookup finds the destination mail server for any domain
  • STARTTLS upgrades plain SMTP to encrypted — mandatory on modern servers
Anti-Spam DNS Records
  • SPF: TXT record listing authorised sending IPs for your domain
  • DKIM: cryptographic signature per email — verifiable via DNS public key
  • DMARC: policy for SPF/DKIM failures — reject, quarantine, or report
  • Gmail and Yahoo (2024): bulk senders must have DMARC. No exceptions.
  • Missing these = email lands in spam or is rejected outright
Blacklisting & Reputation
  • Spam complaint rate >0.1% → Gmail starts filtering your email
  • Spam complaint rate >0.3% → Gmail rejects your email entirely
  • IP/domain blacklists (Spamhaus ZEN) are checked by every MTA on receipt
  • New domain/IP must "warm up" slowly — start with 100 emails/day, scale over weeks
  • Remove unsubscribers immediately; clean bounce lists regularly
Network Topology · Topic 8

LAN · MAN · WAN · VLAN

Networks are classified by their geographic scope. LAN covers a building, MAN a city, WAN the globe. VLANs create logical separation within a physical LAN — the same physical switch can host completely isolated networks.

LAN — <1 km
  • One building, one floor — Ethernet cable or Wi-Fi
  • Layer 2 switching — MAC address forwarding
  • 1–100 Gbps speeds
  • No routing needed — flat network
MAN — 1–50 km
  • City-wide — utility fibre or ISP metro ring
  • Connects multiple buildings or campuses
  • Technologies: MPLS, Metro Ethernet, dark fibre
  • Examples: city council network, university campus
WAN — Global
  • Country to continent — submarine cables, satellite
  • BGP routing between autonomous systems
  • Technologies: MPLS, SD-WAN, internet transit
  • Examples: corporate WAN, the public internet itself
VLAN — 802.1Q
  • Logical network on one physical switch
  • Packets tagged with VLAN ID (1–4094)
  • VLANs cannot communicate without a router
  • Use: isolate HR, Finance, Eng on one switch
Data Centre Architecture · Topic 9

Routers · Load Balancers · Switches in a Data Centre

In a production data centre, traffic flows through a precisely ordered sequence of devices — each operating at a different OSI layer with a specific function. The diagram shows the full path from the public internet to a database server.

Router — Layer 3 Path Selection
  • Border router: speaks BGP to the internet. Announces your IP ranges. Selects best inbound/outbound paths.
  • Core router (L3 switch): routes between VLANs/subnets internally
  • Operates on IP addresses only — does not read TCP ports or HTTP
Load Balancer — Distribute Traffic
  • Sits between the internet-facing tier and the server pool
  • Health-checks each server; removes failed servers automatically
  • SSL termination: decrypts HTTPS here, backend gets plain HTTP
  • URL routing: /api → app servers, /static → CDN origin, /admin → separate pool
Switch — Layer 2 Forwarding
  • Core switch: OSPF routing between VLANs, 10–100 Gbps trunks
  • Top-of-Rack (ToR) switch: one per rack, connects servers at 1–10 Gbps
  • VLANs 10/20/30 enforce tier isolation at Layer 2 — web tier cannot directly reach DB tier
  • Spanning Tree Protocol (STP) or ECMP for redundancy
Security · Topic 10

Firewalls & WAF — Layers of Defence

The data centre diagram from the previous slide has two security layers baked in. A stateful firewall filters at Layer 3/4 (IP + port). A WAF (Web Application Firewall) filters at Layer 7 (HTTP content). Together they implement defence in depth.

🔥 Stateful Firewall (Layer 3/4)
  • Tracks every connection's state: NEW → ESTABLISHED → RELATED → INVALID
  • Rules: allow inbound TCP:443 from any, block TCP:22 from internet
  • Blocks ports you don't use — default deny all, allow specific
  • Technologies: Linux iptables/nftables, pfSense, Palo Alto NGFW, Cisco ASA
  • Position: immediately after the border router — first defence
  • Can also do IPS: Deep Packet Inspection to detect attack signatures
  • Internal firewall between app and DB tiers: only port 5432 (PostgreSQL) allowed from app VLAN — principle of least privilege
🛡 WAF — Web Application Firewall (Layer 7)
  • Reads HTTP request payload — something a stateful FW cannot do
  • Blocks OWASP Top 10 attacks: SQL injection, XSS, CSRF, RFI, path traversal
  • Example rule: block any request containing ' OR 1=1-- in any parameter
  • Rate limiting: block IP after 100 requests/second (DDoS mitigation)
  • Bot detection: JavaScript challenge or CAPTCHA for suspicious user agents
  • Technologies: AWS WAF, Cloudflare WAF, ModSecurity, Imperva
  • Position: after outer firewall, before load balancer — inspects HTTPS after SSL termination
Defence in depth: Border Router (DDoS scrubbing) → Outer Firewall (stateful, port-level) → WAF (HTTP-level) → L7 Load Balancer (SSL, routing) → Core Switch (VLAN isolation) → Internal Firewall (east-west, least privilege) → Database (encrypted at rest). A breach must defeat all six layers sequentially.
Distribution Architecture · Topic 11

CDN → Edge Computing

A CDN caches static content at Points of Presence (PoPs) worldwide — reducing latency from 200ms to 5ms by serving from nearby. Edge Computing goes further: it runs actual application code at those PoPs, eliminating round trips to the origin entirely.

CDN — Content Delivery Network
  • Hundreds of PoPs in every major city — Cloudflare has 310+, Akamai 4000+
  • Static assets (HTML, CSS, JS, images, video) cached at nearest PoP
  • DNS directs user to geographically nearest PoP automatically (Anycast or GeoDNS)
  • Cache hit: served from PoP in <5ms · Cache miss: fetches from origin, caches for TTL
  • Major providers: Cloudflare, Akamai, AWS CloudFront, Fastly, Azure CDN
Edge Computing — Code at the PoP
  • V8 isolates (Cloudflare Workers) or lightweight containers run at each PoP
  • Your JavaScript/Rust/Go function executes in <1ms, returns result — origin never called
  • Cold start: ~0ms (persistent isolate) vs Lambda's ~100ms
  • Insurance example: premium calculator runs rating tables at Mumbai edge — user types, gets quote as they type, no spinner
  • Platforms: Cloudflare Workers, AWS Lambda@Edge, Fastly Compute@Edge, Vercel Edge Functions
More Edge Use Cases
  • JWT verification: authenticate every request at the edge — block before origin
  • A/B testing: edge splits traffic, no origin involvement, zero latency
  • Personalisation: edge reads cookie, serves personalised HTML — faster than server-side rendering
  • Gaming: matchmaking server at nearest edge node — 5ms vs 200ms
  • Healthcare: patient triage chatbot at edge, works even with poor connectivity
Advanced Networking · Topic 12

Software Defined Networking — Programmable Infrastructure

Traditional networks configure each device individually. SDN separates the control plane (routing decisions) from the data plane (packet forwarding) — a centralised controller programs all switches via API, making the network as programmable as software.

Physical Spine-Leaf — The Foundation
  • Any server reaches any other server in exactly 2 hops (leaf → spine → leaf)
  • All spine-leaf links are equal cost — traffic distributed across all spines
  • Predictable latency, maximum east-west bandwidth (server-to-server)
  • Scale out: add a leaf switch, connect to all spines — done
  • Each device configured individually: VLAN, ACL, OSPF per switch
SDN — Centralised Control
  • Control plane (SDN controller): computes routes, holds global topology view
  • Data plane (dumb switches): just forward packets per flow table rules
  • Southbound API (OpenFlow, NETCONF): controller pushes rules to switches
  • Northbound API (REST/gRPC): Kubernetes/OpenStack requests network segments
  • Provision a new VLAN: one API call → controller pushes to all switches in seconds
  • VXLAN overlay: virtual Layer 2 networks tunnelled over Layer 3 physical fabric
When to Choose Which
  • Physical spine-leaf: stable large data centres, bare-metal performance, proven hardware, lower operational complexity when team knows physical networking
  • SDN/Overlay: cloud-native environments, Kubernetes clusters, rapid VM provisioning, multi-tenant isolation without hardware reconfiguration
  • Hybrid (most common): physical spine-leaf fabric + SDN overlay on top (VMware NSX, Cisco ACI)
  • SD-WAN: SDN applied to WAN — controller picks best path (MPLS vs internet vs 4G) per application class
